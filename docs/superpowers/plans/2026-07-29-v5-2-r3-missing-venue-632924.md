> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Create one disjoint, source-only r3 authority that excludes exactly MLB gamePk 632924 because its authenticated 2021 schedule object has no usable venue identity, while preserving every r2 and parent-evidence byte.

**Architecture:** R3 is a new sealed source run, not a continuation or repair of r2. A run-scoped recovery-disposition interface selects an authenticated catalog: r2 remains its unchanged three-record/three-query compatibility branch; r3 has four disposition records but exactly three derived schedule projection query IDs. In r3, the two 2021 records (the existing 633224 conflict and 632924 missing venue) share one authenticated 2021 combined projection query, which removes both closed sets before one schedule/anchor projection. This prevents a duplicate 2,429-anchor 2021 population. All source products consume that one post-projection r3 population so no venue, boxscore, game-inventory, snapshot, or checkpoint entry can reintroduce 632924.

**Tech Stack:** Python 3.11, unittest, JSON Schema Draft 2020-12, canonical JSON/SHA-256, Git-bound source authority, Ruff.
