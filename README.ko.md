# MLB Walk-Forward Lab

[English README](README.md)

MLB 경기 시작 전에 예측을 기록하고, 공식 결과가 나오면 같은 기록으로 정산하는 연구 프로젝트입니다. 2026년 9월 운영은 9월 30일 16:18 EDT에 종료했고, 정기 점검은 계속 일시정지 상태입니다. 이 저장소에는 당시 코드와 보고서, 검증 근거를 보존합니다.

공식 기록은 **사전 등록 24건, 공식 정산 23건, 적중 10건(43.5%)**입니다. 정규시즌 세 경기일의 소표본으로, 모델 개선이나 베팅 우위를 입증하지는 못했습니다.

## 무엇을 했나

```text
MLB 공식 일정 + Statcast + 경기 전 참가자 정보
    → 입력 검증 → 예측 보고서와 입력 추적 기록(trace)
    → 시작 전 최초 적격 예측 봉인
    → 공식 Final 대조 → 정산과 영수증(receipt)
```

Python 워크플로는 예측과 그 근거를 정산과 분리해 저장합니다. 재실행으로 진단을 추가할 수는 있지만 최초 적격 예측을 바꿀 수는 없습니다. 포스트시즌 연구 기록은 정규시즌 성과 집계와 분리합니다. 총점 비교는 오차 진단에만 사용했고, 정식 O/U 수익은 산출하지 않았습니다.

## 왜 운영을 멈췄나

첫 포스트시즌 연구 실행은 예측을 쓰기 전에 중단됐습니다. 연기일과 재편성일에 동일 경기 ID가 등장했고, 일정 정규화보다 중복 검사가 먼저 실행됐습니다. 사용자는 그날 정기 점검을 일시중지했습니다. 이후 공통 파서를 수정하고 격리 검증으로 입력 문제를 확인했지만 운영은 재개하지 않았습니다. 11월 9일 기준 사전 예측부터 공식 Final까지 검증할 새 포스트시즌 경기는 없었습니다. 실경기 검증은 미수행으로 남기며, 이 보관 작업의 종료 조건으로 삼지 않습니다.

## 남길 것과 다음에 다르게 할 것

- **최초 예측과 영수증을 남깁니다.** 예측이 언제 존재했는지 입증할 수 없으면 전향적 성과로 세지 않습니다. 시작 전에 놓친 예측은 성과 기록에서도 누락으로 남깁니다.
- **결과 옆에 분모를 적습니다.** 저장 행, 적격 예측, 공식 정산은 서로 다른 질문에 답합니다. 입력 데이터가 아무리 많아도 실시간 성과 표본이 커지지는 않습니다.
- **원본 데이터 계약부터 시험합니다.** 실제 연기·재편성 사례로 경기 ID를 대조하고, Statcast 행 상한을 확인한 후에만 날짜 구간을 완전하다고 판단합니다. 거부된 원본과 사유도 보존합니다.
